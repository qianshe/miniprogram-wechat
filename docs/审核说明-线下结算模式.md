# 微信小程序审核说明 - 线下结算模式

## 一、业务定位

本小程序为殡葬服务展示与需求登记平台，采用"线上展示 + 意向登记 + 线下履约"的业务模式。

**核心定位**：
- 服务展示平台：展示殡葬用品、殡葬服务、套餐方案等信息
- 需求登记工具：用户浏览后提交意向单，记录服务需求
- 线下履约模式：所有交易、支付、服务履约均在线下完成

**目标用户**：
- 需要殡葬服务的家属
- 通过小程序了解服务内容，线下沟通确认后完成交易

## 二、服务流程

完整的用户使用流程如下：

1. **浏览阶段**：用户在小程序中浏览殡葬商品、套餐、服务流程等信息
2. **意向登记**：用户选择感兴趣的商品/套餐，提交意向单（非订单）
3. **人工沟通**：商家通过电话/微信与用户沟通，确认具体需求和服务细节
4. **线下结算**：双方线下见面，确认服务方案，现场支付（现金/转账/刷卡）
5. **服务履约**：商家按约定提供线下殡葬服务
6. **收款记录**：商家在管理端记录线下收款情况，完成流程闭环

**关键特征**：
- 小程序内无任何在线支付入口
- 所有"订单"实为"意向单"，用于记录用户需求
- 最终交易金额、支付方式均在线下协商确定

## 三、为何采用线下结算

### 3.1 行业特殊性

殡葬服务具有以下特点，不适合标准化在线交易：

- **服务高度定制化**：每个家庭的需求、预算、文化习俗差异大，无法用标准商品SKU描述
- **需要深度沟通**：涉及敏感话题和重要人生时刻，需要面对面或电话详细沟通
- **价格弹性大**：根据服务规模、地域、时间等因素，最终价格需要协商确定
- **履约周期长**：从下单到服务完成可能跨越数天，中间需要多次调整

### 3.2 线下履约必要性

- **现场确认**：殡葬仪式等服务必须在线下实地完成
- **物品交付**：花圈、寿衣等实物需要现场交付和确认
- **服务调整**：现场可能根据实际情况调整服务内容和人员配置
- **信任建立**：敏感服务需要面对面建立信任关系

### 3.3 用户体验考虑

- **避免误解**：如果提供在线支付，用户可能误以为是标准化电商，导致期望偏差
- **灵活协商**：线下支付允许用户与商家协商付款方式（分期、定金等）
- **退款便利**：如服务未履约或需要调整，线下退款更灵活

## 四、技术实现

### 4.1 意向单系统

小程序内的"订单"实为"意向单"，技术实现如下：

- **数据结构**：记录用户选择的商品/套餐、数量、联系方式、备注需求
- **状态流转**：待确认 → 已确认 → 已收款 → 已完成
- **无支付接口**：代码中不包含任何微信支付API调用
- **文案规范**：所有按钮文案为"提交意向单"、"联系确认"，不出现"支付"字样

### 4.2 管理端线下收款记录

商家通过管理后台记录线下收款：

- **收款记录功能**：管理员可标记意向单为"已收款"，记录实际收款金额、方式、时间
- **金额可调整**：实际收款金额可能与意向单金额不同（协商调整后）
- **备注说明**：可记录收款方式（现金/转账/刷卡）和特殊说明
- **流程闭环**：通过管理端操作完成从意向登记到收款确认的完整闭环

### 4.3 关键代码说明

- `api/order.js`：提供意向单创建、查询功能，无支付相关方法
- `cloudfunctions/orderManagement`：云函数处理意向单逻辑，包含 `recordOfflinePayment` 方法用于记录线下收款
- `pages/order/confirm`：意向单确认页，按钮文案为"提交意向单"
- `pages/admin/order/list`：管理端订单列表，提供"确认线下收款"操作

## 五、用户体验保障

为确保用户充分知情，小程序采取以下措施：

### 5.1 明确提示

在关键页面添加免责声明和业务说明：

- **意向单确认页**：显著位置提示"本小程序仅用于展示与需求登记，最终以电话/微信沟通及线下结算为准"
- **订单详情页**：说明当前状态为"意向登记"，等待商家联系确认
- **首页/关于页**：说明平台业务模式和服务流程

### 5.2 无支付入口

- 购物车页面按钮为"提交意向单"，不是"去支付"
- 订单列表中待确认订单的操作按钮为"联系确认"，不是"去支付"
- 订单详情页无任何支付相关按钮或倒计时

### 5.3 状态透明

用户可随时查看意向单状态：

- **待确认**：已提交意向单，等待商家联系
- **已确认**：商家已联系并确认服务方案
- **已收款**：线下已完成支付
- **已完成**：服务已履约完成

## 六、管理端功能

### 6.1 意向单管理

管理员可查看所有用户提交的意向单，包括：

- 用户联系方式
- 选择的商品/套餐明细
- 意向金额（参考价）
- 用户备注需求

### 6.2 线下收款记录

管理员确认线下收款后，可在系统中记录：

- 实际收款金额（可能与意向金额不同）
- 收款方式（现金/微信转账/支付宝/刷卡等）
- 收款时间
- 备注说明（如定金、尾款等）

### 6.3 服务跟踪

管理员可更新意向单状态，跟踪服务进度：

- 标记"已确认"：表示已与用户沟通确认服务方案
- 标记"已收款"：表示线下已完成支付
- 标记"已完成"：表示服务已履约完成

## 七、总结

本小程序采用"展示 + 登记 + 线下履约"的完整业务闭环，符合殡葬行业的实际业务特点。小程序内不提供在线支付功能，所有交易均在线下完成，通过管理端记录收款情况实现流程闭环。这种模式既满足了用户线上浏览和需求登记的便利性，又保证了服务的定制化和线下履约的必要性。
